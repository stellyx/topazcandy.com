# Website enquiry form

Topaz Candy's information, service-discussion and template-enquiry buttons use `/contact/`, with an allowlisted service and optional template context. They do not open an email or SMS app. The short form asks for name, reply email, and a website or project note. Business name, phone and service selection are optional details. Website input uses a URL keyboard, accepts a bare domain and validates an http/https URL; it does not load the visitor's website, create an iframe or open a new tab. A sample brief may be passed in the fragment, which is removed after prefill and is not transmitted with the HTTP page request. No personal details are stored in browser storage.

The fixed, activated FormSubmit endpoint already used by checkout sends enquiries to the established business mailbox. `assets/topaz/form.mjs` sends a form-encoded cross-origin POST, requires an explicit positive provider response, rejects the honeypot, blocks concurrent sends and preserves fields on failure. An unchanged accepted message is not sent twice; failed retries keep the same reference. The enquiry payload cannot choose a recipient/CC or create an order/payment. FormSubmit documents a 30-day archive; the opaque public form destination is not a private account credential.

`comments.html` now uses the same automatic delivery, preserves anonymous/optional-rating feedback and records explicit permission to publish comments and display name. Reply email is optional and stays private. No comments are automatically published. The separate real-client MJ adaptation retains its previously authorized stylist booking/contact routes; this update changes Topaz Candy's own and the generic template's enquiry paths. Explicit phone calls remain available as phone actions.

Checks: `node scripts/check-contact.mjs` and `node scripts/check-purchase.mjs`. A labelled synthetic enquiry using the actual model and form-encoded endpoint was received in the business inbox on 2026-10-11. The provider returned HTTP 200, success=true and Access-Control-Allow-Origin: *. No real customer information or payment was used. Browser/device visual QA and a completed PayPal payment were not performed in the managed environment.
